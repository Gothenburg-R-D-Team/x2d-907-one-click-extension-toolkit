# X2D/907 One-Click Extension Toolkit — Project Policy / 项目政策

## 中文

### 1. 整个官方项目持续免费

本政策适用于 [X2D/907 One-Click Extension Toolkit（X2D/907 一键扩展功能工具包）](https://github.com/Gothenburg-R-D-Team/x2d-907-one-click-extension-toolkit)
的官方维护工作，覆盖本项目的全部软件、安装工具及未来功能。

官方承诺现在和未来持续免费提供项目软件，不出售软件、不收费下载或访问，
不设置订阅、付费解锁、付费专享功能或付费提前访问。不得通过指定购买其他商品
或服务来变相收取软件费用。官方也不收费提供本软件的安装、设置、配置或部署服务。

维护者承诺不以项目名义提供另行付费分发许可，不通过单独书面批准绕过上述原则，
也不通过将同一项目改名、迁移仓库或设立收费版本来规避这些承诺。

完全自愿的捐赠可以接受，但不购买任何软件访问、功能、提前访问或安装服务权益。

### 2. 允许商业摄影

用户可以将软件用于商业摄影、收费拍摄、影棚工作、客户委托以及出售摄影成果，
无需向项目支付软件使用费或摄影收入分成。

### 3. 源码与发布对应

每个采用新许可公开发布的官方安装包，须在发布时同步免费公开其对应的项目源码、
构建脚本、依赖信息和构建说明，并用版本标签或提交及源码归档明确对应关系。
只公开旧版源码或不同分支的源码不视为履行该承诺。源码链接的最低保留期限依
[LICENSE](LICENSE) 执行。

内部 Beta 用于协作、安全检查和测试，可以暂不向公众发布。向测试者分发二进制时，
仍须向其提供对应源码，不额外限制许可证赋予他们的权利。任何公开提供的 Beta
安装包也属于公开发布，适用同步公开源码的要求。

第三方材料保留各自许可；项目应说明依赖来源和许可，不提交无权公开的厂商固件、
专有组件或其他受限材料，也不以此为由隐藏受新许可覆盖的项目源码。

### 4. 尊重贡献者

贡献者保留各自贡献的版权，不要求转让版权。项目应保留适用的版权声明和合理署名，
尊重贡献者表达的合理署名偏好，并准确标识第三方材料的来源。

维护者不得把仓库管理权限或一次合并视为版权转让，也不得据此假定贡献者同意
后续更换许可证。适用许可与审阅规则见 [CONTRIBUTING.md](CONTRIBUTING.md)。

### 5. 许可实施与既有贡献

采用或变更项目许可前，应核对受影响材料的来源、原有授权和发布情况，并在需要时
取得相关权利人的明确同意。相关授权尚未确认的材料，应暂缓进一步整合或发布。
若发现已发布材料存在授权问题，应单独处理，不能靠替换 LICENSE 追溯解决。

### 6. 历史权限与本政策的边界

历史 MIT 材料及第三方组件保留原有权限。本政策不声称能够追溯禁止已获授权的
旧版本销售或商业分发。

本文件记录官方治理承诺，与 [LICENSE](LICENSE) 配合使用。删除许可中的收费例外，
本身并不取消版权所有者独立授权其自有代码的能力；本政策另行明确维护者不提供
项目收费授权的承诺。若未来需要加强对这一承诺的约束，应由相关权利人另行明确
约定，不能假定本文件已经构成所有贡献者签署的协议。

政策调整应公开讨论、记录理由并通知受影响贡献者。不得借政策更新默默撤回上述
永久免费和不提供收费授权的承诺，也不得改变已经授予的许可权限。

## English

### 1. The entire official project remains free

This policy applies to the official maintenance of the
[X2D/907 One-Click Extension Toolkit](https://github.com/Gothenburg-R-D-Team/x2d-907-one-click-extension-toolkit),
covering all software, installation tools and future features of this project.

The official project commits to providing its software without charge, now
and in the future. There will be no software sales, paid downloads or access,
subscriptions, paid unlocks, paid exclusive features or paid early access.
Receiving or using the software must not depend on buying another item or
service. The official project will not charge for installation, setup,
configuration or deployment of the Software.

Maintainers commit not to offer separate paid-distribution licenses on behalf
of the project, approve written exceptions to these principles, or evade these
commitments by renaming the same project, moving repositories or creating a
paid edition.

Fully voluntary donations are permitted only if they purchase no software
access, features, early access or installation services.

### 2. Commercial photography is permitted

Users may use the Software for professional photography, paid shoots, studio
work, client commissions and selling photographic deliverables without a
software usage fee or a share of photography revenue payable to the project.

### 3. Source must correspond to releases

Every official public binary release under the new license must have its
corresponding project source, build scripts, dependency information and build
instructions publicly available without charge at release time. A release tag
or commit and source archive must identify the version used. Source from an
older version or a different branch is insufficient. The minimum availability
period for source links is specified in [LICENSE](LICENSE).

Private Beta development may be used for collaboration, safety review and
testing before public release. Recipients of private binaries must still
receive corresponding source, with no additional restrictions on their
licensed rights. Any publicly offered Beta binary is a public release and
must have corresponding source publicly available at the same time.

Third-party materials retain their own licenses. Dependencies and their
licenses must be identified. Vendor firmware, proprietary components and
other materials the project has no right to publish must not be committed.
These exclusions must not be used to withhold covered project source.

### 4. Respect for contributors

Contributors retain copyright in their respective contributions. No copyright
assignment is required. The project should preserve applicable copyright
notices and reasonable credit, respect contributors' reasonable stated credit
preferences, and accurately identify the origin of third-party materials.

Repository administration or a merge is not a copyright assignment and must
not be treated as consent to a later license change. See
[CONTRIBUTING.md](CONTRIBUTING.md) for licensing and review rules.

### 5. License adoption and existing contributions

Before adopting or changing the project license, maintainers must check the
origin, existing permissions and release status of affected materials, and
obtain explicit agreement from relevant rights holders where necessary.
Further integration or release of materials whose authorization remains
unresolved must wait for clarification. If an existing release has an
authorization problem, it must be addressed separately; replacing LICENSE
does not fix it retroactively.

### 6. Historical permissions and limits of this policy

Historical MIT materials and third-party components retain their existing
permissions. This policy does not claim to retroactively prohibit sales or
commercial distribution already permitted for earlier versions.

This document records official governance commitments alongside
[LICENSE](LICENSE). Removing the license's paid-use exception does not itself
eliminate copyright holders' independent ability to license their own code.
This policy separately states the maintainers' commitment not to offer paid
project licenses. Any stronger arrangement should be expressly agreed by the
relevant rights holders; this document must not be presented as an agreement
already signed by all contributors.

Policy changes must be discussed publicly, explained and communicated to
affected contributors. They must not silently withdraw the commitments to a
permanently free official project and no paid project licenses, or change
permissions already granted.
